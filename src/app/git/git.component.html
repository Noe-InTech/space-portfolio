Git

Git est un outil incontournable pour tout développeur souhaitant travailler sur des projets collaboratifs ou structurés. Il permet de suivre précisément l’évolution du code, de collaborer efficacement à plusieurs sur une même base de code, et de garantir une traçabilité fiable dans les projets. J’ai découvert Git très tôt, dès mes premiers projets personnels, et j’ai rapidement compris qu’il allait devenir une pièce maîtresse de mon environnement de développement.

En expérimentant les commandes de base (commit, push, pull, merge, rebase), j’ai appris à garder un historique clair et à éviter les conflits. C’est dans le cadre du projet Covoit’Santé que j’ai utilisé Git de façon professionnelle pour la première fois, en suivant une approche Git Flow : branche principale stable, branches de fonctionnalités et de corrections, revues de code, déploiement automatisé via GitLab CI/CD. J’ai aussi géré des pull requests et participé activement aux décisions d’intégration.

Sur le projet Optivex, j’ai approfondi mes compétences en gestion de version : tagging pour les livraisons, utilisation de Git bisect pour identifier l’origine de bugs, et structuration de l’historique pour assurer une maintenance sur le long terme. L’intégration des hooks Git m’a permis d’automatiser des vérifications de formatage de code avant chaque commit, améliorant ainsi la qualité du projet.

Travailler avec Git m’a également permis d’améliorer ma gestion des conflits. J’ai appris à utiliser git rebase dans les bonnes situations, à réécrire l’historique proprement avec git commit --amend ou git reset, et à éviter les mauvaises pratiques qui mènent à des branches difficiles à maintenir. Ces réflexes sont devenus des automatismes que je partage souvent avec mes camarades ou collègues moins expérimentés.

Aujourd’hui, Git fait partie intégrante de mon workflow. Je l’utilise quotidiennement, que ce soit pour des projets personnels ou en équipe. Je suis à l’aise avec la majorité des commandes avancées, ainsi qu’avec l’utilisation de plateformes comme GitHub, GitLab ou Bitbucket. Je maîtrise également les pipelines CI/CD pour déclencher des tests ou déploiements à chaque push.

Je considère avoir un bon niveau en Git, que j’ai acquis principalement par la pratique, en résolvant de vrais problèmes dans de vrais projets. Cela m’a permis d’aller au-delà de l’usage basique et de réellement comprendre ce qui se passe “sous le capot” du versionning.

Je continue d’approfondir certains aspects : GitOps pour la gestion d’infrastructure par Git, les submodules pour gérer des dépôts imbriqués, ou encore la gestion fine des permissions dans des dépôts partagés. J’explore aussi les stratégies de release avancées, comme les monorepos ou les flux trunk-based.

Avec le recul, je dirais qu’il est essentiel de comprendre que Git n’est pas seulement un outil de sauvegarde, mais une véritable base de communication pour une équipe. Bien utiliser Git, c’est écrire un historique lisible, compréhensible, et savoir comment isoler les modifications pour mieux collaborer.

Je souhaite renforcer ma maîtrise de Git en environnement professionnel avec des outils comme GitHub Actions, GitLab Runner, ou Bitbucket Pipelines. Je me forme actuellement sur ces outils et les bonnes pratiques d'automatisation et de sécurisation des dépôts dans un contexte DevOps.
